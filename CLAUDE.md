## Project Overview

MultipackParser is a bridge application connecting Multipack palette optimization software with Universal Robots (UR10/UR20) palletizing systems. It parses `.rob` files generated by Multipack, stores them in a SQLite database, and serves the data to robot controllers via XML-RPC.

**Key Technologies:** PySide6 (Qt6), XML-RPC, SQLite, Matplotlib (3D visualization), Pygame (audio)

## Development Commands

### Running the Application

```bash
# Development mode with debug logging
python main.py --verbose

# Standard run
python main.py

# Disable virtual keyboard (useful for testing on non-touch displays)
python main.py --no-virtual-keyboard

# Check version
python main.py --version

# Show license
python main.py --license
```

### Building

```bash
# Build ARM64 binary using Docker (default)
python build.py

# Build with Nuitka instead
python build.py --dockerfile Dockerfile.nuitka
```

The binary is placed in `output/` directory and is ARM64-compatible (for Raspberry Pi deployment).

### UI Development

```bash
# Edit UI in Qt Designer
pyside6-designer ui_files/MainWindow.ui

# Convert UI to Python (REQUIRED after editing)
pyside6-uic ui_files/MainWindow.ui -o ui_files/ui_main_window.py

# Convert resource files
pyside6-rcc ui_files/MainWindowResources.qrc -o ui_files/MainWindowResources_rc.py
```

**CRITICAL:** After running `pyside6-uic`, manually change the import in `ui_files/ui_main_window.py`:
```python
# Change from:
import MainWindowResources_rc

# To:
from . import MainWindowResources_rc
```

## Architecture Overview

### Layered Architecture

```
main.py (Entry Point)
    ↓
UI Layer (utils/ui/)
    ↓
Service Layer (utils/server/, utils/robot/, utils/database/, utils/audio/)
    ↓
Core Layer (utils/system/core/)
```

### Key Components

**Global State Management (`utils/system/core/global_vars.py`)**
- Centralized application state
- Contains VERSION constant, robot status, palette/package data
- Uses global variables that are accessed across modules
- Key data structures: `g_PalettenDim`, `g_PaketDim`, `g_PaketPos`, `g_Daten`

**Settings (`utils/system/config/settings.py`)**
- JSON-based configuration with encrypted passwords
- Robot model selection (UR10 vs UR20)
- Audio settings, admin credentials

**Database (`utils/database/`)**
- SQLite database (`paletten.db`) with 8 normalized tables
- Main table: `paletten_metadata` with 7 child tables via foreign keys
- Database schema auto-migrates (adds columns if missing)
- Key functions: `create_database()`, `save_to_database()`, `load_from_database()`

**XML-RPC Server (`utils/server/`)**
- Listens on port 8080
- Three modules: `UR_Common_functions.py`, `UR10_Server_functions.py`, `UR20_Server_functions.py`
- Server started in background thread
- All RPC calls are logged

**Robot Control (`utils/robot/`)**
- Status monitoring via Dashboard Server (port 29999)
- Uses enumerations: `RobotMode`, `SafetyStatus`, `ProgramState`
- Continuous polling in background thread

**UI Layer (`utils/ui/`)**
- `ui_setup.py`: Main initialization orchestration
- Qt Designer files in `ui_files/`: `MainWindow.ui`, `ui_main_window.py`
- Custom widget: `BlinkingLabel.py` for status indicators
- 3D visualization in `visualization_3d.py` using Matplotlib

### Data Flow

1. **Pallet Loading:** USB stick → Parse `.rob` file → Save to SQLite → Update global_vars → Refresh UI
2. **Robot Communication:** Robot XML-RPC request → Server function handler → Access global_vars/database → Return data → Update UI
3. **Status Monitoring:** Background thread polls robot → Update global_vars → Qt signals → Update UI

### Threading Model

- **Main Thread:** Qt event loop and all UI operations
- **Background Threads:**
  - XML-RPC server (multi-threaded request handling)
  - Robot status monitor
  - Audio player
  - Safety monitor

**Thread Safety:** Use Qt signals/slots for cross-thread UI updates. Global variables are accessed from multiple threads without locks (read-mostly pattern).

## Critical Data Structure Constants

Located in `global_vars.py`, these index constants are used throughout the codebase:

```python
# Primary data indices
LI_PALETTE_DATA = 0      # Palette dimensions index
LI_PACKAGE_DATA = 1      # Package dimensions index
LI_LAYERTYPES = 2        # Layer types index
LI_NUMBER_OF_LAYERS = 3  # Number of layers index

# Position array structure (9 values per package)
LI_POSITION_XP = 0       # X position (pick)
LI_POSITION_YP = 1       # Y position (pick)
LI_POSITION_AP = 2       # Angle (pick)
LI_POSITION_XD = 3       # X position (drop)
LI_POSITION_YD = 4       # Y position (drop)
LI_POSITION_AD = 5       # Angle (drop)
LI_POSITION_NOP = 6      # Number of packages
LI_POSITION_XVEC = 7     # X vector
LI_POSITION_YVEC = 8     # Y vector
```

Always use these constants when indexing into data arrays.

## Robot Type Specific Code

The application supports two robot models (UR10 and UR20) with different capabilities:

- **UR10:** Single palette, simpler scanner system
- **UR20:** Dual palettes with active palette switching, advanced scanner monitoring

Robot type is determined by `settings.settings['info']['UR_Model']` and affects:
1. Which XML-RPC functions are registered
2. UI elements displayed
3. Status monitoring behavior

When adding robot-specific features, follow the pattern in `utils/server/`:
- Common logic → `UR_Common_functions.py`
- UR10-specific → `UR10_Server_functions.py`
- UR20-specific → `UR20_Server_functions.py`

## Environment Setup Notes

**Critical Environment Variables** (set in `main.py` before Qt imports):
```python
os.environ["QT_X11_NO_MITSHM"] = "1"
os.environ["LIBGL_ALWAYS_SOFTWARE"] = "1"
os.environ["QT_OPENGL"] = "software"
os.environ["QT_QPA_PLATFORM"] = "xcb"
```

These force software rendering to avoid OpenGL issues on Raspberry Pi.

**Virtual Keyboard:** Set `QT_IM_MODULE=qtvirtualkeyboard` (controlled by `--no-virtual-keyboard` flag)

## Important Patterns

**Lazy Imports:** Heavy modules (PySide6, matplotlib) are imported after argument parsing to speed up `--version` and `--license` flags.

**Splash Screen Progress:** Application shows loading progress during startup. Update via:
```python
progress.setValue(percentage)
loading_label.setText("Status message...")
app.processEvents()
```

**Logging:** Two separate loggers:
- Application logger: `logs/multipack_parser_*.log`
- Server logger: `logs/server_*.log`

Use `--verbose` flag for DEBUG level logging.

**Password Protection:** Admin settings require password authentication. Passwords stored encrypted. USB key file can bypass password entry.

## Database Schema Notes

The database uses a normalized schema with foreign key constraints (`ON DELETE CASCADE`). When modifying:
1. Add migrations in `create_database()` using try/except on ALTER TABLE
2. Maintain foreign key relationships
3. Update both save and load functions in `database.py`

Primary table is `paletten_metadata` with `file_name` index. All other tables reference `metadata_id`.

## Common Pitfalls

1. **UI File Changes:** Always regenerate Python code after editing `.ui` files and fix the import statement
2. **Global Variables:** Import `global_vars` module, not individual variables: `from utils.system.core import global_vars`
3. **Robot IP:** Hardcoded to `192.168.0.1` in `global_vars.py` - DO NOT CHANGE without coordinating with robot-side code
4. **USB Path:** `PATH_USB_STICK` defaults to `'..'` for development but should point to actual USB mount in production
5. **Server Port:** XML-RPC server runs on port 8080 (defined in `server.py`)
6. **Thread Safety:** Always use Qt signals for UI updates from background threads

## Testing Considerations

This application requires:
- UR robot hardware (or simulator) for full integration testing
- Multipack-generated `.rob` files for testing palette loading
- Robot-side URscript code (not included in this repo) for XML-RPC testing

For development without hardware, mock the robot connections in `robot_control.py`.

## Release Process

GitHub Actions automatically builds and releases when:
1. Python files change on `main` branch
2. VERSION in `global_vars.py` doesn't match existing git tag

To release a new version:
1. Update `VERSION` in `utils/system/core/global_vars.py`
2. Commit and push to `main`
3. GitHub Actions builds ARM64 binary and creates release
