## Project Overview

MultipackParser is a C++ Qt6 application that bridges Multipack palette optimization software with Universal Robots (UR10/UR20) palletizing systems. It parses `.rob` files generated by Multipack, stores them in a SQLite database, and serves the data to robot controllers via XML-RPC.

**Key Technologies:** C++17, Qt6 (Widgets, Network, Sql, Multimedia), XML-RPC, SQLite, VTK (optional 3D visualization)

## Development Commands

### Building

```bash
# Native build (macOS/Linux)
./build.sh
./build.sh --debug --run      # Debug build and run
./build.sh --clean            # Clean before build

# Native build (Windows)
build.bat
build.bat --debug --run

# ARM64 cross-compilation for Raspberry Pi
./docker-build.sh             # macOS/Linux
docker-build.bat              # Windows (equivalent to docker-build.sh)
build.bat --arm64             # Windows (alternative)
```

Output binaries are in `build/bin/` (native) or `output/` (ARM64).

### Running the Application

```bash
# From build directory
./build/bin/multipack-parser

# With options
./build/bin/multipack-parser --verbose
./build/bin/multipack-parser --no-virtual-keyboard
./build/bin/multipack-parser --version
./build/bin/multipack-parser --license
```

### UI Development

```bash

pyside6-designer ui/MainWindow.ui
```

## Architecture Overview

### Namespace Structure

```
multipack::
├── core::           # Application core, global state
├── config::         # Settings, logging configuration
├── ui::             # MainWindow, dialogs, widgets
├── database::       # SQLite database operations
├── network::        # XML-RPC server
├── robot::          # Robot communication
├── audio::          # Audio playback, safety monitor
├── message::        # Status/message management
├── system::         # USB monitoring, file operations
└── utils::          # String, socket, validation utilities
```

### Key Components

**Global State (`core/GlobalState.h`)**
- Singleton managing all application state
- Thread-safe with QMutex
- Emits Qt signals on state changes
- Contains: palette dimensions, package data, robot status, scanner state
- Access via: `GlobalState::instance()`

**Data Index Constants (`core/GlobalState.h` → `DataIndices` namespace)**
```cpp
namespace DataIndices {
    constexpr int PaletteData = 0;
    constexpr int PackageData = 1;
    constexpr int LayerTypes = 2;
    constexpr int NumberOfLayers = 3;
    
    // Position array indices (9 values per package)
    constexpr int PositionXPick = 0;
    constexpr int PositionYPick = 1;
    constexpr int PositionAnglePick = 2;
    constexpr int PositionXDrop = 3;
    constexpr int PositionYDrop = 4;
    constexpr int PositionAngleDrop = 5;
    constexpr int PositionCount = 6;
    constexpr int PositionXVector = 7;
    constexpr int PositionYVector = 8;
}
```

**Settings Manager (`config/SettingsManager.h`)**
- JSON-based configuration stored in `settings.json`
- Password encryption: SHA256 with random salt (format: `salt_hex$hash_hex`)
- Robot model selection (UR10 vs UR20)
- Validation methods for all setting types

**Database Manager (`database/DatabaseManager.h`)**
- SQLite database (`paletten.db`)
- Normalized schema with foreign key cascades
- Auto-migration for schema changes
- Key operations: `saveToDatabase()`, `loadFromDatabase()`

**XML-RPC Server (`network/XmlRpcServer.h`)**
- Listens on port 8080
- Methods split by robot type:
  - `URCommonFunctions.cpp` - shared functions
  - `UR10ServerFunctions.cpp` - UR10-specific
  - `UR20ServerFunctions.cpp` - UR20-specific
- All RPC calls are logged

**Robot Controller (`robot/RobotController.h`)**
- Dashboard Server client (port 29999)
- Status monitoring in background thread
- Enumerations: `RobotMode`, `SafetyStatus`, `ProgramState`

**Audio System (`audio/`)**
- `AudioManager.h` - Qt Multimedia playback
- `AudioQueue.h` - Queued playback with counting
- `SafetyMonitor.h` - 30-second scanner warnings

### Data Flow

1. **Pallet Loading:** USB stick → `RobFileParser` → `DatabaseManager::save()` → `GlobalState` → UI signals
2. **Robot Communication:** XML-RPC request → `RpcMethodRegistry` → handler function → `GlobalState` → response
3. **Status Monitoring:** `RobotStatusMonitor` thread → `DashboardClient` → `GlobalState` → Qt signals → UI

### Threading Model

- **Main Thread:** Qt event loop, all UI operations
- **Background Threads:**
  - XML-RPC server (multi-threaded request handling)
  - `RobotStatusMonitor` (polling loop)
  - `AudioQueue` (playback thread)
  - `SafetyMonitor` (warning timer)
  - `UsbMonitor` (device detection)

**Thread Safety:** All cross-thread communication uses Qt signals/slots with `Qt::QueuedConnection`. GlobalState uses QMutex for data access.

## Robot Type Specific Code

The application supports UR10 and UR20 with different capabilities:

| Feature | UR10 | UR20 |
|---------|------|------|
| Palettes | Single | Dual with switching |
| Scanner | Basic monitoring | Advanced with zones |
| UI Elements | Single palette view | Dual palette tabs |

Robot type is set in `settings.json` → `info.UR_Model` and affects:
1. Which RPC functions are registered (`UR10ServerFunctions` vs `UR20ServerFunctions`)
2. UI elements displayed
3. Scanner monitoring behavior

When adding robot-specific features:
- Common logic → `URCommonFunctions.cpp`
- UR10-specific → `UR10ServerFunctions.cpp`
- UR20-specific → `UR20ServerFunctions.cpp`

### Platform-Specific Notes

**Raspberry Pi (ARM64)**
- Use `docker-build.sh` for cross-compilation
- Environment variables set in `main.cpp`:
  ```cpp
  qputenv("QT_X11_NO_MITSHM", "1");
  qputenv("LIBGL_ALWAYS_SOFTWARE", "1");
  qputenv("QT_OPENGL", "software");
  qputenv("QT_QPA_PLATFORM", "xcb");
  ```

**Qt Version Compatibility**
- Target: Qt 6.2+ (Ubuntu 22.04 ships 6.2.4)
- Avoid Qt 6.6+/6.7+ features:
  - Use `stateChanged(int)` not `checkStateChanged(Qt::CheckState)`
  - Don't use `QPalette::Accent` color role

## Important Technical Notes

### Hardcoded Values

| Value | Location | Notes |
|-------|----------|-------|
| Robot IP | `192.168.0.1` | GlobalState default |
| XML-RPC Port | `8080` | XmlRpcServer |
| Dashboard Port | `29999` | DashboardClient |
| Master Password | `eCaXDv6V8EUE8#d!8FTb` | PasswordDialog.h |
| USB Path | `..` (dev) | ConfigDefaults |

### Password Encryption Format

```
salt_hex$hash_hex
```
Where: `hash = SHA256(salt_bytes + password_utf8)`

Compatible with Python version's encryption.

### Common Patterns

**Accessing Global State:**
```cpp
#include "multipack/core/GlobalState.h"
auto& state = multipack::core::GlobalState::instance();
int length = state.paletteLength();
```

**Emitting Signals for UI Updates:**
```cpp
// From background thread - use queued connection
emit stateChanged();
```

**Settings Access:**
```cpp
#include "multipack/config/SettingsManager.h"
auto& settings = multipack::config::SettingsManager::instance();
QString robotModel = settings.value("info/UR_Model").toString();
```

## Testing Considerations

This application requires:
- UR robot hardware (or simulator) for full integration testing
- Multipack-generated `.rob` files for palette loading tests
- Robot-side URscript code (not in this repo) for XML-RPC testing

For development without hardware, mock the robot connections in `RobotController`.

## Release Process

GitHub Actions automatically builds when:
1. Code changes pushed to `feat/cpp-rewrite` or `main`
2. Creates ARM64 binary artifact

To manually release:
1. Update `VERSION` in `CMakeLists.txt` and `ConfigDefaults.h`
2. Tag the commit: `git tag v1.x.x`
3. Push: `git push --tags`
